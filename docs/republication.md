# Повторная публикация вакансий

Поиск по-прежнему использует ссылку пользователя с `search_period=1`.
Монитор сопоставляет видимые ссылки по ID с данными каждой страницы выдачи
и хранит дату в
`monitor-state.json → publicationDates`.

- Для известного ID первая успешно прочитанная дата сохраняется молча.
- Более новая дата у известного ID создаёт уведомление «Вакансия переопубликована».
- Та же дата, дата в прошлом относительно сохранённой или неверная дата не
  создают повторного уведомления.
- Отсутствие вакансии в текущей выдаче или невозможность проверить её дату
  блокируют отправку ранее поставленного в очередь переопубликования.
- После успешной отправки новая дата становится сохранённой. Ошибка Telegram
  оставляет задание для повторной попытки, не помечая его доставленным.

Точное время берётся из `vacancySearchResult.vacancies[].publicationTime.$`
в шаблоне `HH-Lux-InitialState` по `vacancyId`. Карточки не открываются.
Время с часовым поясом
нормализуется в UTC и хранится в `publicationTimes`. Более позднее время
у того же ID вызывает уведомление, даже внутри одного дня. Одинаковое время
с разными часовыми поясами считается одной публикацией. Изменение текста
или `dateModified` не считается переопубликованием.

Первое получение точного времени для уже сохранённого дня происходит молча.
Если точного времени нет или данные неоднозначны, новый ID по-прежнему
может быть отправлен, а переопубликование ждёт подтверждения в следующей выдаче.
Дата не используется как
дополнительный фильтр возраста вакансии: отбор за сутки делает HH.
Новые ID продолжают обрабатываться обычным способом.

Результаты чтения дат и ошибки находятся в `publicationStatus`. Профиль Chrome,
история доставок, очищенный пользователем исходный список и очередь анализа
сохраняются. Перезапуск монитора не сбрасывает сохранённые даты.
